# Input, upload, and menu contracts

A numeric `Input` binds and dispatches a number for valid input and `''` for a genuine clear. Partial invalid edits, such as an unfinished exponent, remain in the native input and do not change the feature value or dispatch an action. The optional `bind:badInput` flag exposes invalid native edits, and `aria-invalid` reflects them. The framework Form blocks submission while a participating native control has bad input; applications do not install validation listeners. Initial values are rendered in server HTML. Equivalent numeric formatting remains intact while typing. This aligns numeric action payloads with the bound value; code expecting every payload to be a string must migrate explicitly.

`fileUploadReducer` owns image preview URLs through per-file subscriptions. Removing a file, clearing the list, or destroying its store releases previews created by the reducer. The `FileUpload` component destroys its internal store on unmount. Headless consumers use ordinary store lifetime management; they do not revoke these URLs themselves. Preview acquisition is optional and failure does not reject an otherwise valid file. Non-images acquire no preview. User-supplied or persisted preview URLs are not adopted as resources; use `filesSelected` to create new upload lifetimes.

`onFilesChange` receives independent snapshots (copied arrays and file metadata), initially for the accepted files and again when optional previews become available. Do not depend on a single callback per selection. Uploading files and their progress remain reducer state. A file's generated ID identifies its lifetime and must not be reused for a replacement. `previewReady` is the framework's resource completion action; exhaustive action consumers must include this new variant. Standard composition must retain scoped effect cancellation for independent instances of the reducer.

A dropdown owns its keyboard listener on its trigger/menu, moves focus into the menu on open, exposes the active command through `aria-activedescendant`, restores trigger focus on Escape or selection, and releases Tab to normal document navigation. Leaving focus or clicking outside closes it without stealing a focusable target's new focus; blank-background dismissal restores the trigger. Item replacement preserves the active command by ID; IDs must be unique and stable across recreated arrays. Removed, disabled, or separator commands cannot remain active. `itemsChanged` is an added action variant for exhaustive consumers.

These guarantees use the current store subscription lifecycle and component boundaries. General managed child replacement, coordinated motion cancellation, and focus coordination across stacked presentation owners remain separate runtime capabilities. A reducer removed from a parent feature must have its effects scoped/cancelled by that composition; root-store destruction is not a substitute for child lifetime management.

See [upload and dropdown lifetime details](./upload-dropdown-lifetimes.md) for AbortSignal, preview URL lifetime, and the native trigger markup migration.
