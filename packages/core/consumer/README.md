# Composable Svelte starter

> The architecture checker is completely optional and its use is discouraged. Its effectiveness on real agent-authored applications is untested as a reliability claim; it is not a reliable way to assess architectural correctness. It can miss violations and reject valid code. Agents must not treat a passing result, including `qualification: "passed"`, as architectural approval or a completion criterion. Follow the application contract, review the source, and test behavior and ownership directly. The checker has implementation tests, but those do not establish its practical reliability.

This is the recommended minimal managed baseline for Composable Svelte
applications. It demonstrates declarative application ownership with
`defineApplication`, `ApplicationRoot`, and `ApplicationHost`, managed
execution, and injected effects.

The included `AGENTS.md` directs coding agents to the installed authoring
contract. Keep that entry point when copying this starter.

Before building features, consult the guides in the installed package:

- Contract: `node_modules/@composable-svelte/core/docs/application-contract.md`
- Ownership: `node_modules/@composable-svelte/core/docs/application-ownership.md`
- Views: `node_modules/@composable-svelte/core/docs/application-views.md`
- Routing: `node_modules/@composable-svelte/core/docs/application-routing.md`
- Motion: `node_modules/@composable-svelte/core/docs/application-motion.md`

Copy this directory out of the installed package into your application directory.
For example, from a directory where core is installed:

```sh
cp -R node_modules/@composable-svelte/core/consumer ../my-app
cd ../my-app
npm install
npm run check
npm test
npm run build
npm run test:ssr
npx playwright install chromium
npm run test:browser
npm run dev
```

Use Node 20.19+ or 22.12+. Commit the lockfile generated by your first install.
The starter uses public npm exports, Tailwind 4, managed application architecture,
and injected effects. Tests cover the reducer's emitted action with managed
execution, SSR state isolation, browser updates and theme.
See the installed core `docs/consumer.md` for architecture and integration guidance.
Satellite README examples are added by the library's release gate, not required
for this minimal application. Configure your own API dependencies before adding
backend-driven features.

## Testing rendered application lifetime

`npm run test:browser` runs the production tests, then a separately built lifetime
fixture. `browser/lifetime/LifetimeHarness.svelte` accepts a children snippet and
provides ordinary Mount/Unmount controls. Put the entire application containing
its `ApplicationRoot` in that snippet. Removing only the Host preserves the
application instance and is not an application-retirement test.

`browser/lifetime/AppUnderTest.svelte` supplies this starter's actual App, initial
state, injected service and production CSS. Adapt that file and the adjacent test
to your application. The test holds real network responses across unmount and
remount, checks fresh state, and verifies the retired response cannot update the
new instance within the observed settlement window. It also checks computed
application styling and browser errors. Await DOM absence before remounting.

The lifetime Vite configuration inherits your production configuration and emits
to `dist-lifetime`, separately from `dist`. Production tests check that the fixture
is absent from production output. Keep the fixture entry out of production build
inputs. If you add routing, deliberately configure the fixture URL and application
route root; do not add a second history writer to the harness. Keep browser timing
native for motion tests and control service responses through dependencies.

The checker is not installed or run by this starter. It is not required for application development, testing, building, or release.
