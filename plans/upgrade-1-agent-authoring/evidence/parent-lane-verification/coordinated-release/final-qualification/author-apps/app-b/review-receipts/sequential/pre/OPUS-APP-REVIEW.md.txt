### Remaining notes (not blocking; not changed)

- **N1 – dependency hygiene.**
  - `@vitest/browser-playwright` is declared but unused.
  - `playwright` is redundant beside `@playwright/test`.
  - These were not removed, to avoid lockfile churn during review; that is a coordinator decision.
- **N2 – duplicated build glue.**
  - `vite.config.mjs` and `vite.config.ts` are identical.
  - `scripts/build.mjs` duplicates `vite build` with `emptyOutDir: false`, which accumulates stale assets.
  - The canonical command is `npm run build`. The pre-review `dist/` is preserved at `review-receipts/pre-review-dist/`.
- **N3 – chart rows are synthesized locally.**
  - `buildActivityMetrics` ignores `subjectId`; only the account email comes from the controlled backend's `fetchAccount`.
  - The root cause is confirmed Gap 1, below.
  - Delayed and reauthentication behavior is still controlled for account load, sign-in, MFA, password change and logout.
- **N4 – `openChangePassword` / `closeChangePassword` root intents.** They forward to the auth child through `Effect.run`. This is small indirection that mirrors the shipped auth consumer's `closeMfaEnrolment` pattern. The guard duplicates the package's own refusal, which is harmless.
- **N5 – `selectedMetric` is justified app-specific state.**
  - It is a typed `AccountActivityRow` projection of the committed chart selection for the account banner.
  - It is set only by the reducer from routed typed chart actions, and cleared with the account.
  - It could instead be derived at render time.
- **N6 – form placement.** The change-password form renders in the single auth outlet above the dashboard, not inside the Security section. This is cosmetic.
- **N7 – SSR proof scope.**
  - `scripts/ssr.mjs` proves three isolated roots (anonymous seeded login, authenticated dashboard, anonymous unseeded) with no cross-request leakage.
  - It shows zero calls to the counted backend operations (login, MFA verify, account, password, logout), both immediately and after 60 ms.
  - It shows that no startup ran: no login flow was created on the server.
  - It does not compare equal-input determinism, and the dashboard session fixture is hand-built JS.
  - The re-reviewer confirmed routing never reduces `navigate` on the server (`core/dist/application/routing.js`).
- **N8 – test rigor.**
  - The TestStore tests use `exhaustivity = 'off'` and never call `finish()`.
  - The author's test 8 (delayed password change after logout) uses an abort-honoring deferred service, so it proves transport abort rather than a dropped late callback. The review's abort-ignoring account-load test with a negative control covers that boundary.
  - No unit test covers a non-handoff subject change on the login route (re-review note).
  - No browser test covers Forward during logout.
  - Pointer/click chart selection has no browser test; keyboard selection does.
- **N9 – out of brief scope.** No session resolution on page load, so a reload returns to sign-in. A failed account load has no retry control.
- **N10 – N/A here.** This app uses no media devices, so "fake device tests do not prove physical microphones" does not apply.

## Checklist from the brief

- **Explicit ownership and freshness.**
  - The app root reducer owns the route: pure `request`/`serialize`, documented vetoes, and no history listeners.
  - It owns the account load: a cancellable effect, an epoch and a subject owner.
  - Auth composition, flows, session epochs and flow retirement are package-owned via `createAuthFeature()`, used unmodified.
  - The chart reducer is `chartReducer<AccountActivityRow>`, used unmodified.
- **Documented acceptance.**
  - Route changes happen only on `handoff.kind === 'accepted'`. Rejected sign-ins, MFA-pending and refused handoffs do not navigate (TestStore plus browser).
  - The password result is read from the one-reduction `changePasswordOutcome`, and the account is kept or replaced by subject id, not object identity.
- **Retirement.**
  - Logout or a subject change clears the former account's data, chart and selection.
  - The account load is cancelled and its epoch invalidated.
  - Auth retires its own settings/flows owners.
  - The delayed-after-retirement cases are the author's test 8 plus the review's paired abort-ignoring account-load tests.
- **Anti-patterns:** none in `src`. There are no repeated Store facades or `createStore`, no copied package reducers, no `subscribeToActions` or `observeChildActions`, and no `$effect`/`onMount` business work. After R5 there is no callback-based managed business routing. There are no ownership casts (the only cast is a data literal `as AuthError` in the controlled backend), no fabricated views, and no duplicated lifecycles (Root/Host/FeatureViews own everything).
- **Typed composition.**
  - `optionalSlot` + `ManagedIntegrationBuilder` + `defineViews` over `auth.composition` and the chart slot.
  - Genuine `PresentationFeatureViewProps` views, with managed-mode `LoginForm`, `MfaChallengeForm` and `ChangePasswordForm`.
  - The test helpers are typed after round 2.
- **Inactive checker rules.** No checker was run, so every architecture obligation above rests on this named manual review plus type evidence (tsc and svelte-check at 0) and runtime evidence (TestStore, browser, SSR). The coordinator's controlled checker must still run.

### Proof that the injected backend is called, cancelled, and stale results rejected

Each item is a TestStore case in `tests/dashboard.test.ts`:

- **Called per subject.** Ada gets 7 rows and the MFA subject gets 3 exact rows. `fetchActivityCalls` goes 1 → 2.
- **Cancelled on logout.** The captured `activitySignals[0].aborted` flips to `true` on logout. The abort-ignoring service still delivers late, and the state stays signed out, with no account, no chart and `accountLoading` false. The paired `logout=false` control accepts the same late result.
- **Superseded same-subject request.** The old signal is aborted, the new one is not, and the old late result is dropped while the load stays pending with an unchanged epoch. Only the current result is accepted.
- **Partial failure.** When `fetchActivity` rejects, the whole load fails: `accountError` is set and there is no partial account or chart.
- **Mutation controls** (`r6-refresh/mutation-controls.txt`, source restored and verified with `cmp`):
  - m1: no cancel on retire.
  - m2: m1 plus no epoch gate.
  - m3: uncancellable load.
  - m4: m3 plus no epoch gate.
  - m5: partial failure tolerated.
  - Each is caught by at least one test. The epoch gate alone is proven by the public stale `accountLoaded` test (m2/m4). In the injected-service tests, core's managed retirement drops the late callback before the reducer sees it, which is defence in depth.
