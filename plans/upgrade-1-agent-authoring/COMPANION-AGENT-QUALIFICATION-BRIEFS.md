# Final installed-reference agent qualification

This implements the existing T7 scope. Dispatch only after final runtime versions and archives are independently reviewed and frozen. App authoring may proceed while checker/profile packaging finishes; install the final reviewed checker and independently pinned policies before final app qualification and acceptance. No archived migration task is reopened for authoring. Use fresh CLI conversations and isolated workspaces; do not inherit migration history, repository source, private skills or prior fixture implementations. The coordinator supplies installed public artifacts, hashes, exact compatible dependency pins and the task brief. Normal iteration is expected; there is no first-attempt score or elapsed-time cutoff.

## Required brief A: conversation workspace

Build a small support conversation workspace with the installed Chat, Code and Media packages. A user can open a conversation, edit a draft in a code editor, attach or display supported media, send a message through a deterministic transport, and close or replace the conversation. Use the library's public managed composition and packaged components. Keep durable application outcomes in the parent reducer. The finished UI should expose the actual features, not just mount hidden components to satisfy imports.

Acceptance observations: a completed assistant response is recorded once by the application; editor commands affect the intended live editor; a recording/transcript belongs to its original conversation; closing or replacing a conversation prevents late work from mutating its successor; a second conversation remains independent. Use fake device/transport dependencies for reproducible automation and explicitly distinguish them from real microphone qualification. Optional integrations must be installed only when used. Include browser interaction and SSR checks where supported.

This is the mandatory Chat+Code+Media composition from T7. It checks the new command seam, business outcome ownership, asynchronous work and optional package composition in actual agent-written application code.

## Required brief B: authenticated account dashboard

Build a small account dashboard using Auth and Charts. The user signs in, handles an MFA challenge if requested, views an account chart, changes a password and logs out. A controlled backend should make successful requests, reauthentication requirements and delayed responses reproducible. The app must explicitly own navigation and account loading while using package-owned auth composition and real chart row types. Keep the scope to these representative flows; do not reconstruct every Auth component demo.

Acceptance observations: accepted sign-in changes the app route; rejected/stale results do not; password/session results follow documented acceptance rather than inferred object identity; logout or a subject change removes the former account's views and pending work; typed chart interactions route through the owning feature. SSR creates independent request roots and performs no client-only work. Include at least one delayed response after retirement in an application-level test.

This probes the substantially new Auth reference and account-owned presentation across packages. It is not a request for another Auth implementation or a production identity backend.

## Required outputs and review

Retain each final app, its tests, the exact package/lock/CLI versions, the iteration and repair log, and a concise account of information missing from installed references. No manual root checkout assistance is allowed; if the author asks for repository-only knowledge, record and repair the public-reference gap rather than quietly supplying it.

The independent final reviewer assesses correctness, explicit ownership, freshness, code factoring and unnecessary application glue. In particular inspect repeated Store facades, copied package reducers, root action-stream listeners, callback-based managed business routing, ownership casts and duplicated lifecycle orchestration. Record justified application-specific state or freshness bookkeeping rather than treating every extra line as a defect. Line counts may describe results but are not acceptance thresholds.

Run intended bundled developer profiles and independently pinned external qualification controls against the same final app and artifacts. An inactive checker rule is not automatically enforced; use the named independent review plus type/runtime evidence for those obligations. Fix concrete package/guidance defects in their owning scope and repeat only affected qualification. Completion is about the resulting app and reference usability after normal iteration.
