# Anchor metadata follow-ups

These proposals ground the Opus P1 follow-up in current public source. They classify potential authority for the five bounded detector families. They do not prove runtime capability genuineness or add ownership/Host enforcement. Field names below are proposed anchor-table data; root owns hook implementation.

| Public identity | Source-backed signature | Proposed metadata |
| --- | --- | --- |
| `@composable-svelte/core/application` `ManagedComposition` | Exported **type-only** from `application/index.ts`; runtime instances come from `ManagedIntegrationBuilder.build()`. It is not exported by the public root or `/navigation` entry point. Public members include `reducer` and `execution`, but only `reducer` matters to the current authority model. | `{ kind: 'authority-type', authority: 'composition' }` for type seeding. Also extend the existing builder metadata with `methods: { with: { result: 'builder' }, forEach: { result: 'builder' }, build: { result: 'composition' } }` so runtime composition values have a producer without spelling method names in flow hooks. |
| `@composable-svelte/core/application` `ApplicationRoot` | Props are `definition: ApplicationDefinition`, `options: ApplicationOptions`, and `children: Snippet<[ApplicationInstance]>`. `ApplicationOptions` requires `dependencies` and exactly one `initial.input` or `initial.state`; routed definitions additionally require `initial.url`. The component invokes `children(app)`. | `{ kind: 'root-component', attributes: { definition: { role: 'definition' }, options: { role: 'root-options', dependencyPaths: [['dependencies']], dataPaths: [['initial']] } }, childSnippet: { prop: 'children', parameters: [{ index: 0, result: 'app' }] } }`. The dependency path is wiring evidence only; never invoke a dependency factory. |
| `@composable-svelte/core/application` `ApplicationHost` | Public wrapper props are `{ app: ApplicationOwner; children: Snippet }`; `children` receives no argument. The internal `owner` compatibility branch is not exported through the wrapper. | Keep `{ kind: 'host-component' }`, optionally add `attributes: { app: { role: 'app-input' } }, childSnippet: { prop: 'children', parameters: [] }`. It consumes existing app authority and creates no new value seed. |
| `@composable-svelte/core/application` `FeatureViews` | Props are `store: ManagedProjection`, `definition: ViewDefinition`, and `children: Snippet<[ViewHandles]>`; it invokes `children(views)`. | Replace the shared generic component record with `{ kind: 'feature-views-component', attributes: { store: { role: 'store-input' }, definition: { role: 'view-definition-input' } }, childSnippet: { prop: 'children', parameters: [{ index: 0, result: 'views' }] } }`. |
| `@composable-svelte/core/application` `FeatureOutlet` | Its only public prop is `view: FeatureView`. It has no consumer `children` snippet. Internally it resolves instances and supplies props to declared render/content views; that internal snippet is not a source-level consumer child. | `{ kind: 'feature-outlet-component', attributes: { view: { role: 'feature-handle-input' } }, childSnippet: null }`. Do not seed `children(views)` at an Outlet site. |
| `@composable-svelte/core/application` `FeatureViewProps`, `PresentationFeatureViewProps`, `FeatureViewPropsOf` | `FeatureViewProps` has `store: ChildView`, `views: ViewHandles`, `surface: Action<HTMLElement>`. `PresentationFeatureViewProps` replaces `store` with `PresentationView`; `FeatureViewPropsOf` derives the same map from a composition. | Keep `kind: 'feature-props-type'` and add `properties: { store: { authority: 'view' }, views: { authority: 'views' }, surface: { kind: 'surface-action' } }`. Both store variants are potential `view` authority for the five detectors; metadata must not claim genuine presentation identity. `surface` is a framework action marker, not element authority until invoked by a native `use:` site. |
| `svelte` `tick` | Svelte declares `tick(): Promise<void>`. The bounded lifecycle-dispatch policy includes callbacks passed to `tick().then(...)`, while an arbitrary Promise `.then` is not automatically a Svelte lifecycle site. | `{ kind: 'lifecycle-promise', result: 'tick-promise', callbackMembers: { then: { callbackArguments: [0], lifecycle: 'tick' } } }`. Match the resolved `tick` import and the returned promise identity; do not classify by the names `tick` or `then`. |
| `@composable-svelte/core/application` `managedDismissDependency` | `managedDismissDependency(cleanup?)` accepts `(signal?: AbortSignal) => void | PromiseLike<void>` and returns a zero-argument `DismissDependency`; invoking that function returns an `Effect`. It is publicly exported only from `/application`. | `{ kind: 'managed-dismiss-factory', cleanupArgument: 0, result: 'dismiss-dependency', invokeResult: 'effect' }`. The cleanup callback runs when the effect executes, not when the factory is called. This metadata records a known framework dependency/effect path; it does not mint a view or generic dispatch authority. |
| root, `/application`, and `/navigation` `scopeTo` | Managed overload: `scopeTo(ManagedProjection, SlotHandle) -> ChildView | undefined`, with `PresentationSlotHandle -> PresentationView | undefined`. Legacy overload: `scopeTo(Store) -> ScopeBuilder`; `.into(...)` returns another builder, while `.case(...)` and `.optional()` return legacy `ScopedStore | null` containing only `state` and `dispatch`. Calling one-argument `scopeTo` on a managed projection throws. | Replace the unconditional result with `{ kind: 'view-scope', overloads: [{ arity: 2, arguments: { store: 0, slot: 1 }, result: 'view', capability: 'managed-projection' }, { arity: 1, arguments: { store: 0 }, result: 'scope-builder', capability: 'legacy-fluent' }], methods: { into: { result: 'scope-builder' }, case: { result: 'legacy-view', capability: 'legacy-read-dispatch' }, optional: { result: 'legacy-view', capability: 'legacy-read-dispatch' } } }`. The dedicated `legacy-view` result remains potential view-like authority for dispatch detection while preserving that fluent results are not managed dismissal authority. It exposes neither `subscribe` nor `select`; those members do not exist on `ScopedStore`.

The relevant public specifiers must remain exact import-origin identities: application components, props, `ManagedComposition`, and `managedDismissDependency` are `/application`; `tick` is `svelte`; `scopeTo` is intentionally available from the root, `/application`, and `/navigation`. Package-internal source paths are not additional public anchors.
