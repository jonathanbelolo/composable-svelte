# Upgrade 1 template integration review

Reviewed 2026-09-22 against the live parser, context, flow, framework seeds, zones, anchors, and the public Root/Views/Outlet source. This is a bounded integration design, not checker qualification. The five existing families remain routing, presentation orchestration, pure decisions, resource orchestration, and competing motion playback. Genuine capability identity, Root equivalence, lifetime/Host ownership proof, and later motion APIs remain outside this change.

## Decision

Implement the two-file template pass, then compose it with the existing flow and zones. Reuse current snippet identities and argument transfer. The original held packet was close, but needed concrete source-correlation and execution-edge corrections; it has been revised in `jobs/template-seeds-gemini-v1.json`. Do not dispatch a stale copy. External dispatch is coordinator-owned; this review made no external calls.

The older `SNIPPET-INTEGRATION-NOTES.md` describes the prerequisite before implementation. Current context already exposes `snippets`, `renderCalls`, and `snippetFor`; current flow already seeds snippet atoms, binds their synthetic TypeScript parameters, and restricts ordinary invocation to render calls. Do not implement this again.

## Actual APIs and smallest prerequisite changes

- `context.snippets` maps stable IDs to `{id,module,marker,scope,binding,parameters}`. Parameters are synthetic TypeScript declarations, so `flow.invokeLocal` handles their existing binding patterns. `snippetFor` accepts a unit, not a node. `renderCalls` is a Set of TypeScript calls, not a map of marker records.
- `flow.invokeLocal(value,args,node)` transfers arguments; it does not append a call fact or zone edge. A template invocation therefore also needs a `callbackSites` entry. Its argument objects are `{node,value,spread}`. `flow.property` is available on both hook and returned APIs.
- `flow.domain.atom('component', origin.path)` takes a string ID. Origins and flow already preserve local component identity; do not mint a second ID from filename guesses or an object argument.
- A marker expression maps to the unique semantic unit with matching original `start/end`, followed by unwrapping the synthetic outer parentheses. Do not compare every node's clamped `nodeSpan`, which can make wrapper and child appear identical.
- Native element ownership was absent from the original exposed markers. Coordinator has added `native-element` for `RegularElement`, carrying `{name,node,scope,span}`. Match a directive/attribute by object identity in `owner.node.attributes`, not source proximity. Dynamic element/component cases outside the supported boundary receive explicit diagnostics.
- Coordinator has added `flow.revision`, combining internal and heap revisions, so template/flow integration can converge without private-field access.
- Coordinator has added `lifecycleSites` to zones alongside existing `wiringSites` and `callbackSites`. Ordinary event handlers are callback sites, not lifecycle sites. Framework seeds already recognize Svelte lifecycle/rune calls.
- Coordinator has also added `UseDirective.actionUnit` for bare `use:action`: its callback is `node.name`, while `node.expression` is the optional second argument. It is a correlated action-name expression unit in the directive scope, validated against the compiler-provided name and exact source interval. This supplies a real context node for the callback edge, including when the action is inside an otherwise inert snippet. Falling back to the script declaration's node would attribute the wrong execution owner.

## Bounded implementation sequence

1. **Source and identity helpers.** Resolve component roots in the marker lexical scope and project dotted suffixes using flow properties; classify only resolved import anchors. Index exact marker/unit correlations and local component origins. Fail deterministically for claimed but unsupported syntax; do not reject all unrelated Svelte syntax.
2. **Framework snippet edges.** Seed only the direct snippet named `children` at Root or FeatureViews. Direct means an actual child of that component's fragment. Root provides potential app; FeatureViews provides potential views and any known declaration handles. ApplicationHost invokes its children without supplying authority. Also model explicit `children={snippet}` attributes. Record callback execution separately. For a direct declaration, use `snippet.binding.declarations[0].node` as the callback site: its declaration scope identifies the caller; the parameter/body scope would produce a self-edge. Root within an unused outer snippet must stay inactive.
3. **Wiring and native callbacks.** Project Root options dependencies without invoking factories. Record the exact dependency expression where available, otherwise the actual containing options expression and projected dependency Value. Do not classify every options function as a lifecycle callback: the public Root options does not define such a contract. Seed native `bind:this` into bindings/property locations, not only the current expression node. Transfer the element to local use/attach callbacks and record their execution. Explicitly record native event Attribute/OnDirective callback sites; the zone engine must not infer execution merely from arbitrary function references.
4. **Exact local component props.** Resolve to the inspected component module; seed stable props heaps into unshadowed instance `$props()` calls and only the corresponding legacy instance export-let bindings. Include direct snippet props by existing identity. Passing a snippet does not execute it: the inspected child's render tag owns that edge. Unsupported executable implicit children cannot silently disappear.
5. **View renderer props and activation.** Anchored `defineViews` takes declarations at argument 1. Preserve the schema's slot/case/nested-definition relationships with stable Values/heaps. Seed potential `{store:view,views:views}` into content snippet parameters or exact render component props. Parameter propagation is not execution. Link consumed FeatureViews definitions to handles and activate a content snippet only through the actual FeatureOutlet `view` expression. Conservatively union known alternatives where needed; exact Root/ownership proof is unnecessary. Never activate arbitrary callbacks merely because they are reachable in a declarations object. An unused content definition must stay inert. Inspected render component modules retain the current conservative instance roots; no new component reachability proof is required.
6. **Compose and converge.** Build framework hooks first and create flow with a guarded template hook because `buildValueFlow` solves immediately. Then create the template pass, alternate `template.apply()` and `flow.solve()` until `flow.revision` stabilizes under a bounded pass limit, and fail closed on non-convergence. Join hook return Values; preserve framework `onProperty`. Construct zones with all three template site collections. Merge template errors into final completeness before running/accepting the existing rule result. Do not activate certification merely because this pass completes.

## Acceptance evidence

Tests must use real temporary projects through parse/context/flow/zones. The minimum causal controls are: Root/Views direct children versus nested/differently named children; shadowed and dotted imports; Root inside an unused snippet; Host children; dependency factory registration without execution; native versus component bind:this and a property target; action-name versus action-parameter interpretation; attach factory return; snippet argument/destructuring transfer; exact `$props`/legacy export-let crossing without same-name leakage; local snippet props used versus unused by the child; known nested/case declarations; consumed Outlet content versus an unused definition; native event callback propagation inside rendered versus inert snippets; repeated apply/solve idempotence; explicit unsupported correlations.

The new tests should establish actual findings or zone membership where execution matters, not just parameter taint. Existing snippet controls provide reuse evidence but cannot by themselves qualify framework-generated children, local props, or native callbacks. Run targeted parser, snippet, flow, zone, framework, and rule suites after integration; other agents own independent adversarial checks. No broad repository audit or new detector family is required.

## Real blockers and remaining boundary

The native ownership, execution-site output, and convergence gaps were small prerequisite/API gaps, not reasons to redesign the checker. Coordinator has implemented the use-directive callback correlation identified by this review; the revised packet now names that actual API. The template file itself and its causal tests remain implementation work. Final qualification still depends on the package/install/fresh-agent gates in PLAN.md, not on the existence of this design note.

This design does not promise genuine PresentationView identity, exact lifetime ownership, sibling/Root substitution detection, or a guarantee that every inspected component module is dynamically reached. Those are distinct from the five bounded families and must not be smuggled into template-seeding acceptance criteria.
